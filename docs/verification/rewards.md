# 积分奖励变更验证

日期：2026-09-21。

## 业务约定

- 新账户初始 500 分；连续签到按 README 精确日程发奖，第 101 天起每日 500 分，断签从第 1 天开始。保留旧账户余额、历史到账金额和当日防重记录。
- 广告每天按成功领取顺序奖励 200、500、1,000 分，最多三次；跳过不占次数，北京时间跨日重置。
- 用户明确选择分享不限次数、每笔 100 分，返回后自行确认。打开转发面板与返回页面不会自动发奖；同一笔分享确认只发一次。客户端不声称微信验证发送成功，后端记录 self-reported。
- 钱包与好友页通过同一 shares.ts 保存待确认标识，已提交确认不可直接丢弃，使用原请求恢复到账结果。

## 验证结果

- `npm run check`：TypeScript 检查、构建及 39 项测试通过。涵盖签到 1～102 天、特殊日期、旧记录、广告三档、跳过与跨日、并发限额、分享取消、重复确认、跨用户隔离和原请求恢复。
- `node scripts/visual-review.mjs`（本机 Playwright + Chrome）：29 个页面状态 × 320/390px，共 58 个布局检查通过，没有水平溢出或页面脚本错误。新增三次广告完成/到账、分享待确认/到账及好友页待确认快照。
- 手动查看钱包窄屏完整页面与第三档 1,000 分领取弹层；保持现有绿色账本样式和原生按钮约定。
- Premium strict 静态审计：0 errors / 0 warnings；报告在 premium-audit.json。静态工具不解析 WXML/WXSS，不能替代页面验证。
- `git diff --check` 无空白错误。共享 token 与 DESIGN.md 不变，未安装或升级依赖。

## 验证边界

页面测试使用实际编译控制器与模拟微信 API，布局使用 Chromium 代理渲染，均不等同于真实微信验收。尚无 AppID、云环境和广告位，因此没有进行真实转发、真实视频或云事务联调，也没有部署。云端启用新功能前需按 cloudbase/database.json 增加 share_sessions 集合并禁止客户端直接读写。
